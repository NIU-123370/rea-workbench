# 技术决策记录

状态：V0.1 规划稿，以下能力和 Workbench 命令尚未实现。每项记录均包含选择、原因、放弃方案和重新评估条件；实现状态以实际代码和验证记录为准。

- D01｜选了：在 REA 上新增独立的本地单人 Workbench 控制层；为什么：复用已有 CLI/MCP 与 Evidence 契约，同时保持 REA 内核的分析职责；放弃了：把前端、容器调度和代码生成直接塞入 REA domain；何时重看：多个调用方出现确实应由 REA 共享的分析语义。
- D02｜选了：TypeScript、Next.js、React Flow、Monaco，以及独立 Node.js worker；为什么：统一边界类型并将浏览器交互与长任务生命周期分开；放弃了：同时维护 Python 中枢和 TypeScript 前端、在 HTTP 请求内运行长任务；何时重看：真实 provider 或测量结果证明另一运行时能解决当前栈无法承担的约束。
- D03｜选了：固定公开 REA 6.4.0 提交 `98d8470d36cfbf7cd25820a4ed430aebae20c0c5`、Node.js 24.18.0 和 npm 11.16.0，源码引用使用该提交的公开永久链接，另行克隆源码后锁文件安装；为什么：独立五文档包仍可定位可复核基线；放弃了：把文档包当可运行程序、依赖上级目录碰巧有源码、自动升级宿主无关软件；何时重看：上游正式调整契约或工具链，重新核对并整体升级文档基线。
- D04｜选了：Web URL 的主动受控采集与 HAR 1.2 离线导入作为完整闭环；为什么：能在有限目标范围内验证采集、证据、蓝图、SDK 和差分链路；放弃了：首版支持所有二进制、APK、JAR、DLL 与动态协议；何时重看：V0.1 的真实工作流、故障恢复与隔离验收稳定通过。
- D05｜选了：ASAR 离线静态分析为 P0，安排第 3–5 天实现与验收，并明确动态行为未知；为什么：ASAR 是归档，不包含运行任意 Electron 应用所需的完整平台条件，但静态支路仍是首版范围；放弃了：静态支路落到后续版本、任意 ASAR 拖入后即可在 Linux 容器运行的承诺；何时重看：具备完整发行包、匹配 runtime、native dependencies 和经过验证的启动契约。
- D06｜选了：SQLite WAL 加本地按摘要存储的不可变文件，唯一 worker 持有运行期数据库连接和写队列，离线迁移器仅在 worker 停止后持同一排他锁写入，Web/API 仅经本机 RPC 查询或提交命令；为什么：让单机事务、引用完整性与写入顺序由一个 owner 保证；放弃了：Next.js/API 与 worker 分别连接 SQLite、多进程直写、首版引入分布式存储；何时重看：多人协作、跨机访问或实际容量与并发测量超出单机需求。
- D07｜选了：通过 REA 的公开 MCP 契约和已解析 Evidence 接入，保存原始身份与限制；为什么：让证据解释保持单一归属并兼容上游语义；放弃了：按日志文本、自由格式字符串或工具目录顺序猜测结果和操作；何时重看：公开契约无法表达已证实的使用需求，且存在可验证的上游扩展方案。
- D08｜选了：保留 `observed / derived / inferred`、authority、来源、coverage 和 unknown gap，三色仅投影 claim 与 edge；为什么：局部事实、推导、因果和缺失覆盖具有不同证明力度；放弃了：把工具成功、人工确认或节点全局状态等同于已观察事实；何时重看：REA 正式改变证据契约，或用户研究证明需要增加展示维度但无需丢失原有语义。
- D09｜选了：observed 显示绿色、derived/inferred 显示黄色、未解决缺口显示红色，人工 approve 单独记录；为什么：确认交接意图不能提高证据证明力度；放弃了：手动涂绿、百分制置信度替代来源、用绿色宣称所有分支正确；何时重看：出现需要独立展示的冲突或过期维度，且已有可执行的投影规则。
- D10｜选了：以目标快照和所需局部主张选择子图，所需黄/红主张、矛盾、过期和覆盖缺口均阻断可构建蓝图；为什么：避免把观察到的一个样本推广为未经证明的业务契约；放弃了：只检查节点颜色、人工批准黄主张后当成观察事实、自动把推断路由和字段可选性作为已证实规范；何时重看：后续版本为实验性草稿提供独立标记、权限和验收，且不混用已验证交付物。
- D11｜选了：Inspector 与 Builder 使用独立进程、上下文、文件视图和工具权限；为什么：隔离必须可由系统权限与读取审计验证；放弃了：只靠角色提示词、共享完整历史或隐藏 UI 字段；何时重看：引入新的执行后端时，需要重新证明相同的数据访问边界。
- D12｜选了：Builder 只读取不可变已批准蓝图中的脱敏 spec/schema 与公开 test vectors，写独立候选目录；为什么：最小化上下文并使交接内容可审计；放弃了：Builder 访问原始 Evidence、源码、Inspector 上下文、REA、网络或 Docker socket；何时重看：新增交付类型确实需要额外数据，且可先形成独立批准的最小交接契约。
- D13｜选了：评估器保留未向 Builder 暴露的 holdout，公开样本与 holdout 分开报告；为什么：降低对已知样本反复修补造成的虚假通过；放弃了：把所有预期输出和失败细节反馈给 Builder 后仍声称独立验证；何时重看：评估方法变化时重新审查泄漏通道、样本身份和通过口径。
- D14｜选了：V0.1 交付 TypeScript HTTP SDK 与 OpenAPI，差分只验证请求序列化和响应解析；为什么：这是 HAR 和受控 mock 能直接检验的行为范围；放弃了：用 HTTP 样本证明后端业务、完整应用或未观察分支等价；何时重看：获得明确函数级 I/O、状态前置条件和实际运行验证能力后增加独立重实现产品范围。
- D15｜选了：比较策略显式版本化，原始样本与比较视图分开保存；为什么：JSON、字节、重复 query、空值与缺失值不能被隐式归一化混淆；放弃了：默默删除时间戳、排序数组、猜测敏感字段或容忍未声明差异；何时重看：新增协议格式需要格式专用比较器，并有真实样本证明其规则。
- D16｜选了：固定 `contractRevision` 及报告 identities 的八项 `snapshotDigest / blueprintDigest / candidateDigest / vectorSetDigest / planDigest / inventoryDigest / comparatorDigest / runnerImageDigest` 后出具 `PASS / FAIL / UNKNOWN`；为什么：验证结论只能对应具体输入、计划、库存与比较环境；放弃了：零样本、跳过、失效或不完整结果显示 PASS，以及任一输入变化后复用旧绿灯；何时重看：新增输入身份时同步报告、决策清单、失效规则与测试。
- D17｜选了：宿主上的受限 broker 持有容器调度权限，目标和 UI 均不接触 Docker socket；为什么：把高权限基础设施与不可信页面、Agent 输入分离；放弃了：privileged、宿主根目录挂载、目标直接控制 Docker、宣称容器绝对安全；何时重看：面向高风险样本时评估虚拟机或更强隔离，并单独验证其能力。
- D18｜选了：非 root、只读根文件系统、受控临时空间、明确资源限额和逐跳网络策略；为什么：限制目标与生成代码的资源和网络影响，同时让覆盖缺失可解释；放弃了：仅靠浏览器请求拦截防 SSRF、无限输出和默认访问宿主网络；何时重看：实际测量或新目标类别要求调整限额、授权网络范围与隔离机制。
- D19｜选了：`/api/v1` 命名契约、严格字段校验、幂等请求、revision 冲突和可续传事件；为什么：重试、断线和并发 UI 操作必须保持任务身份与状态一致；放弃了：前端根据自由文本猜测状态、目录顺序绑定 handler、静默覆盖新版本；何时重看：协议出现破坏性变化或新增客户端无法使用当前传输。
- D20｜选了：job 与 cleanup 分别建模，`queued` 在启动前永久失败或重试截止时可转 `failed`，暂不可用按期限留队，`POST /projects/:p/jobs/:j/cleanup-retry` 只重试资源回收；为什么：业务结果、进程终止和回收是不同事实且必须可恢复；放弃了：清理重试重新执行业务、清理失败丢弃 lease、仅凭 PID 和路径认定所有权；何时重看：新增资源类型时为其补充身份与回收证明。
- D21｜选了：数据本地保存，默认离线生成和离线验证，认证凭据与显式敏感值按结构和声明排除；为什么：延续 REA 的本地证据和明确脱敏规则；放弃了：默认上传证据到云模型、按 token/password 等名字猜测秘密、持久化子进程继承的整个环境；何时重看：用户显式启用外部服务时先增加独立的数据出境契约与测试。
- D22｜选了：将洁净室描述为可审计的数据交接与访问隔离流程；为什么：来源授权、行为规范和第三方协议仍需单独评估；放弃了：百分之百合法、百分之百干净或全部软件等价的承诺；何时重看：交付对象或使用场景变化并获得对应授权与专业评估后更新适用范围。
- D23｜选了：发布前冻结输入、运行真实公共工作流、备份数据库与摘要文件清单，并保留可恢复旧版本；为什么：假 provider、页面截图和单元测试不能证明真实运行及迁移安全；放弃了：未经备份自动迁移、拷贝单个 WAL 数据库文件当完整备份、跨不兼容 schema 直接降级；何时重看：增加多用户或服务部署时重新设计停写、备份一致性与恢复目标。
- D24｜选了：不可信候选执行器与可信 fixture/evaluator 分容器和文件视图，evaluator 产生报告，经唯一 worker 校验后落库和发布；为什么：Builder 隔离不能阻止生成代码在运行时偷看 oracle；放弃了：候选自报请求或 PASS、候选与 holdout 共用文件权限；何时重看：新执行后端接入时重新验证请求观测、输出行为和评估权限边界。
- D25｜选了：上传触发异步 ingestion，在 staging lease 有效时完成 REA 唯一来源分析，随后使用持久 Evidence；为什么：脱敏 Evidence 不是可再次解析的原始 HAR；放弃了：长期保留含认证的上传、重启后丢失敏感声明却静默重跑、篡改 Evidence 仍沿用 ID；何时重看：需要可重新分析的授权原始材料库时单独设计访问与保留策略。
- D26｜选了：VectorService 以持久 Evidence 与明确 record 定位提取，通过 `POST/GET /projects/:p/vectors` 创建和读取，Inspector/审阅者补足 `operationId`、`sdkInput` 与 `expectedOutcome` 并保留缺失原因；为什么：样本拥有可定位生产者与读取契约，补充解释不修改或升级 Evidence；放弃了：由 UI 或 Builder 重解析原始 HAR、以人工审核制造观察事实；何时重看：新增格式要求新的来源定位或样本语义时扩展该 owner。
- D27｜选了：样本库存与验证计划分开，冻结计划先于蓝图，契约 requiredCases 引用的全部样本进入 required 集合，修订链旧版本以 superseded 及后继 ID 披露，计划内 blocked 不得删除或降为可跳过来换 PASS，范围外项与理由仍计入库存报告；为什么：允许有限范围交付而完整披露未验证覆盖；放弃了：失败后移出样本、把库存总数当测试通过分母、用范围排除伪造通过；何时重看：范围或样本身份变化时创建新 contract/plan/blueprint 并保留旧结论。
- D28｜选了：DiagnosticsSanitizer 统一拥有错误、日志、事件、审计及契约/蓝图交接前的严格敏感内容检查，覆盖持久错误列，并由 handoff owner 在序列化后再次检查；为什么：同一敏感值不能从诊断或交接旁路泄漏且批准摘要保持有效；放弃了：人工审阅代替检查、静默改写已批准内容、事后改写 Evidence、只过滤成功响应；何时重看：增加内容或诊断通道时补足同一策略与泄漏测试。
- D29｜选了：worker 将访问允许/拒绝与审阅事件写入 `audit_entries`，以 `GET /projects/:p/audit` 提供受限读取，仅保存身份、资源引用、结论与脱敏原因；为什么：权限隔离和拒绝记录必须可核验且不复制受限原文；放弃了：仅靠终端日志证明审计、把原始请求体或证据正文写入审计；何时重看：新增角色、跨项目权限或保存策略时重新审查字段与访问边界。
- D30｜选了：本地启动在终端展示有过期时间的一次性内存 bootstrap secret，页面以 `POST /api/v1/session {bootstrapToken}` 交换 `HttpOnly; SameSite=Strict` cookie、`csrfToken` 和本地 `reviewerId`；为什么：浏览器可建立受保护会话且审批来源可追溯；放弃了：令牌进入 URL/日志、长期静态口令、把本地会话当实名认证；何时重看：引入多用户或远程访问前重新设计认证和授权。
- D31｜选了：DESIGN §14 作为 `WB_*` 配置解析和 `GET /health.effectiveProfiles` 的唯一权威，启动前校验 loopback、绝对路径、已安装 profile 清单与受限 broker socket，容器入口按清单映射；为什么：配置必须能关联真实执行环境且不把宿主地址暴露给目标；放弃了：README 与实现分别解释配置、未知 profile 静默回退、目标继承宿主环境；何时重看：新增宿主或 profile 能力时同步该清单与启动测试。
- D32｜选了：T17 对固定宿主和 fixture 中 1000 条 HAR / 200 节点的 p95 ≤ 1 秒执行首版发布门禁；为什么：PRD 性能目标需要有明确验证者与可复现结果；放弃了：仅写目标不测、把无基线误写为已达标、通过删减输入掩盖慢路径；何时重看：发布前测量证明资源假设需要调整时先修订 PRD 和测试条件并重新评审。
