# REA Workbench 产品需求

版本：V0.1 开发规格。实现状态：未实现。产品定位：本地、单人、证据驱动的软件考古与 HTTP SDK 交付工作台。架构见 [DESIGN](DESIGN.md)，验证见 [TESTPLAN](TESTPLAN.md)。

## 用户与问题

| 用户                             | 当前问题                                     | V0.1 结果                                            |
| -------------------------------- | -------------------------------------------- | ---------------------------------------------------- |
| 接手遗留前端 / Electron 的工程师 | 静态切片、抓包和笔记分散，无法分清猜测与观察 | 一张能定位原始 Evidence、未知项和证据范围的图        |
| 为已有 HTTP 服务补 SDK 的工程师  | 请求格式靠手工抄写，边界响应容易遗漏         | 审阅后的契约、TS SDK、OpenAPI 与逐样本验证报告       |
| 评审重构方案的技术负责人         | 不知道生成代码依据什么，测试通过覆盖了什么   | 固定输入身份、交接清单、权限审计和有限范围的验真结果 |

核心任务：对一个被授权分析的目标，回答“我们实际知道哪些行为、缺什么证据、哪些契约可以交给另一个 Agent、生成的客户端在已观察样本上是否一致”。

## 产品原则

- 原始 Evidence 与来源不可变，显示标签、解释和布局另存。
- 观察、派生、推断、未知分别保留；绿色只针对具体主张及其范围。
- 采集、推理、审阅、生成、比较使用同一项目身份，但不同权限与上下文。
- 成功、部分、不可用、取消和清理失败分别展示；没有数据不能显示为通过。
- 所有持久化与模型推理默认本地；工作台遥测关闭。操作者选择的 Web 采集是显式网络活动。

## 三栏交互

| 区域                   | 展示                                                                  | 关键操作                                         |
| ---------------------- | --------------------------------------------------------------------- | ------------------------------------------------ |
| 左栏 Sandbox & Probes  | 目标身份、采集配置、画面、动作时间轴、网络记录和资源状态              | 导入、开始采集、执行允许动作、停止、选择记录     |
| 中栏 Evidence Canvas   | 模块 / endpoint / function / IPC / model 实体，claim 与关系的证据状态 | 定向调查、查看来源、审阅契约、选择范围、冻结蓝图 |
| 右栏 Clean-Room Studio | 契约与 OpenAPI、代码、验证报告三个 Tab                                | 生成、查看 diff、创建新修订、导出                |

首版画面预览与受控点击/输入动作足够，不要求完整 VNC、任意浏览器脚本或系统调用探针。REA MCP 的 progress 不是网络事件流；界面以工作台事件展示任务进度，以已提交的 Evidence 更新图。只有采集适配器确实提供的事件才逐条展示，不伪造“整条调用链实时亮起”。

## 证据与交付规则

REA `confidence` 的 `observed / derived / inferred` 保持原义。UI 将适用范围内证据充分的 observed 主张投影为 `SEEN`；派生与推断显示 `INFERRED` 并注明原始类别；缺证据、不可用、过期、矛盾等显示 `UNKNOWN` 及具体原因。边单独判断，不能因为两端绿色而变绿。红色表示尚不能确认，不表示行为错误。

人工批准只代表接受某个契约修订，不改变 Evidence 的置信来源。静态代码里见到 URL，不等于观察到请求；HAR 里见到响应，不等于确认了 handler 或后端算法；路径模板和 schema 泛化均可能是推断。

首版严格蓝图只交接证据充分且范围明确的行为。所选范围内 required claims 及关系必须是适用的 observed；黄色 derived/inferred 和红色 UNKNOWN 均阻断冻结，不能隐藏边或人工涂绿绕过。有限样本无法证明的泛化保留在草稿与待调查清单，不能混入“已验证范围”。运行时行为必须有对应可用动态样本，单独静态观察不满足条件。导出时仍携带范围和 unknowns，不承诺覆盖整个实体。

样本由 VectorService 从已持久化 Evidence 产生，保留目标、记录坐标与摘要；经独立审阅明确 `operationId`、`sdkInput` 和 `expectedOutcome`，不能复制候选输出充当预期答案。缺 oracle 或比较必需信息时保留 blocked 样本，仍可在库存中查看，不补造空值。

项目样本库存与验证计划分开：审阅时可对当前契约 scope 之外、不能支持此行为且非 required 的样本逐条登记排除理由和未覆盖行为；矛盾证据或 required 覆盖缺口不能靠排除解决。构建前冻结契约、库存快照和验证计划，所有选定 required cases 都在计划内。冻结后不允许删除 blocked/skipped/unknown 或缩减分母把结果变为 PASS；确需缩小行为范围时创建新契约、计划与蓝图，保留旧结果。

## 明确不做什么

- 不做云端多租户、团队协作、账号计费、公开部署或自动同步原始证据。
- 不做恶意软件安全实验室，不把 Docker 称为绝对隔离；不自动执行上传程序。
- 不支持任意 `.asar` 在 Linux 容器运行，不从 IPC 值形状生成虚构的 payload 样本。
- 不生成后端替代服务，不把客户端 replay 通过宣传成服务端业务等价。
- 不自动重构整套产品 UI，不首发 Python/Rust SDK、WebSocket/SSE/流式协议 SDK 或完整系统调用追踪。
- 不自动推断登录凭据，不把认证值或明确敏感内容交给 Builder，不把名称相似当作敏感判据。
- 不把人工“确认”当成事实，不承诺 100% 正确、全输入等价或自动获得洁净室法律结论。
- 不修改 REA provider 内核，不自动安装/升级宿主分析软件；未来 Ghidra/IDA 仍由用户自备并遵守各自只读与生命周期规则。

## 验收标准

固定发布 fixture 使用本地 HTTP 应用与有明确授权的 HAR，分成独立的验收场景：成功主路径包含成功/错误响应、空正文、Unicode、重复 query 和至少一例 holdout，预期固定计划 PASS；缺失正文、阻断脱敏、矛盾和过期输入作为负向场景，分别预期阻断冻结、UNKNOWN 或 FAIL。测试套件通过表示这些预期均成立，不表示每份评估报告都为 PASS。库存中的非 required、scope 外样本可按审阅规则显式排除；required 缺口不能从成功计划删掉。未知外站的偶然响应不作发布门禁。

| 编号           | 可验证标准                                                                                                                                                                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A01 导入身份   | HAR/ASAR 入库后有摘要、原始来源与记录坐标；同名不同内容不混合；格式错误和越界选择有类型化错误                                                                                                                                    |
| A02 Web 采集   | 显式启动固定 Web 场景，保留 action/transaction/Evidence 关联及正文采集选择；缺体或不可用不能补成空串；预览与取消可用                                                                                                             |
| A03 图的诚实性 | 观察、派生、推断、未知均有示例；点击与请求仅时间相关时不出现 observed 因果边；人工批准不改变置信来源                                                                                                                             |
| A04 恢复幂等   | 同一幂等键不重复启动任务；SSE 按游标恢复不丢已提交事件；旧 revision 返回 409；仅 worker 持 SQLite 写连接，API 通过本地 RPC；重启后 Evidence 可读                                                                                 |
| A05 执行隔离   | Builder 无法读原始证据、Inspector 上下文、holdout 及未授权路径，无法调用 REA、Docker 或外网；候选不能读 oracle 或伪造报告；会话/CSRF 与审计拒绝可验证                                                                            |
| A06 蓝图门禁   | required 黄色 derived/inferred、红色 UNKNOWN、未审阅、证据失配、跨目标、矛盾、过期、缺样本或缺覆盖均阻断；边独立校验；有效范围固定计划与摘要                                                                                     |
| A07 生成物     | 固定 fixture 生成可编译 TS SDK 和通过 3.1.1 校验的 OpenAPI；不自动把样本字段泛化成完整服务规范；生成输入可追溯                                                                                                                   |
| A08 差分口径   | 成功主路径覆盖成功/错误响应、空正文、Unicode、重复 query 及 holdout；故意改坏请求/解析会失败；冻结计划不得删阻断项或缩分母；库存排除与未覆盖范围可追溯                                                                           |
| A09 生命周期   | 超时/取消/崩溃保留 Evidence；队列永久启动失败/到期未启动为 failed；owned 资源清理失败保留 ownership；cleanup-retry 只重试清理，不重跑业务或误删外部资源                                                                          |
| A10 资源与网络 | 执行前公布生效限额；超额在昂贵分配前拒绝，保留此前已提交 Evidence 和 provider 明确返回的 partial observation，不伪造失败分析的部分结果；默认阻断私网、元数据地址及未允许出站，重定向/DNS 变化亦校验；本地 fixture 需独立显式授权 |
| A11 本地与脱敏 | HAR 导入、分析、生成、验证可断网运行；认证与显式敏感值不出现在持久 Evidence、API/SSE、诊断、日志、错误、审计、diff 或导出；ASAR 不支持的敏感声明返回 422                                                                         |
| A12 升级回滚   | 运行中断恢复与已存在项目迁移通过；能从一致性备份恢复 DB+artifact manifest，旧版不读取不兼容新库，不丢操作前证据                                                                                                                  |
| A13 性能门禁   | Linux x64 记录硬件及全部版本，1,000 条 HAR/200 个可见节点下暖态至少 30 次有效图更新，提交至界面 p95 ≤ 1 秒；另报冷态、导入耗时及采集/模型等待                                                                                    |

验证成功标签使用 `verified-samples`，分别显示冻结计划的“通过 / 失败 / 阻断 / 跳过 / 总数”和库存快照的总数、排除、blocked 与未覆盖范围。`counts.total` 只计冻结计划，`inventoryCounts.total` 计完整库存快照（含 excluded/blocked）；`passRate = passed / counts.total`，计划零样本为 `null`。仅当所有计划 required cases 完整、当前、成功且没有 required 覆盖缺口时为 `PASS`；计划内存在跳过、阻断或 unknown，即使执行项全过也不能 PASS。

## 非功能要求

| 项目     | 要求                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 可追溯   | 每个可导出 claim、样本、契约及报告均能追到目标快照和 Evidence；Builder 只获得允许的交接视图                                                                                            |
| 本地权限 | HTTP 仅 loopback，校验 Host/Origin、会话与 CSRF；终端一次性 token 经 POST 建立 HttpOnly/SameSite=Strict 会话，token 不放 URL；目标容器不接触控制平面                                   |
| 一致性   | worker 是唯一 SQLite writer，API 命令/查询通过本地 RPC；Evidence 与事件原子提交，图可重放；长任务与 Web 请求生命周期分离                                                               |
| 性能目标 | 在记录版本和硬件的 Linux x64 基准机上，1,000 个 HAR 记录和 200 个可见图节点的本地交互不阻塞主线程；图更新提交至界面 p95 ≤ 1 秒为 A13 发布门禁；暖态至少 30 次，冷态及采集/模型等待另报 |
| 容量     | 首版默认单个目标执行任务；导入、展开、反序列化、base64 解码、图投影与导出分别计量，实际 profile 限额可见                                                                               |
| 可访问性 | 状态同时用文字/图标表示；画布提供列表视图，错误可复制，关键流程支持键盘                                                                                                                |

## 里程碑与完成定义

| 阶段      | 结果                                           | 退出条件                                     |
| --------- | ---------------------------------------------- | -------------------------------------------- |
| 第 1–2 天 | contracts、fixture、REA 适配与身份探测         | 公共 CLI/MCP 输出可校验并持久化              |
| 第 3–5 天 | HAR、ASAR 静态支路、样本库存、事件日志与白板   | A01/A03/A04/A11；ASAR 只读与敏感声明拒绝通过 |
| 第 6–7 天 | 受控 Web、资源 broker 与 Inspector             | A02/A09/A10；隔离未通过就关闭执行能力        |
| 第 8–9 天 | 样本审阅、契约/计划冻结、Builder、SDK 和比较器 | A05/A06/A07/A08；含保留样本与负向 fixture    |
| 第 10 天  | 发布验证、性能测量、备份回滚、演示             | A01–A13、真实浏览器 lane 与审计记录齐全      |

以上是两周原型排期假设，不能代替隔离、真实模型与恢复验证。P0 未验收时可发布标明能力的内部预览；不得把关闭的能力展示为首版已支持。
